# 易方达真实披露复杂任务评测集 v1

本评测集先于 P1 产品修改引入，独立于原有 `eval/cases.jsonl` 的 20 条虚构资料回归用例。
这里的输入是易方达官网原始中文 PDF，事实和数值来自报告，不生成、改写或重新排版报告充当真实资料。
问题和评审规则由本项目编写；标准答案是基于原报告的标注，不是另一模型生成的答案即被视为正确。

## 2. 内容与文档关联

覆盖：财务指标、收益与基准、跟踪误差、行业配置、前十大股票、债券投资、申赎与份额变动、投资方法和审计状态。

核心关联包括：

1. **前后期衔接**：2024Q4 期末份额与 2025Q1 期初份额应一致，需要两份报告分别作证。
2. **份额合并陷阱**：510100 的单位净值由 1.3320 元变为 2.6644 元；2025Q1 季报第 4 页披露 2025-03-07 份额合并、比例 0.49719902，季度收益为 -0.55%。不能由单位净值相除认定收益翻倍。
3. **份额勾稽**：510100 的期初份额加申购、减赎回、加合并调整等于期末份额。份额下降不能直接推断为净赎回。
4. **持仓交集**：两只基金 2025Q1 前十名股票共有 6 只；未进前十不等于未持有。
5. **状态变化**：510310 在 2024 年末未持有债券，2025 年 3 月末持有亿纬转债。
6. **分母差异**：资产组合表按总资产计算，行业配置表按净资产计算；两个占比不能直接判为矛盾。
7. **同结论多来源**：四份报告都说明主要采用完全复制法、财务资料未经审计；聚合后仍应保留四份来源身份。
8. **不同口径排名**：基金收益排名与相对各自基准的超额排名可能不同；正超额也可能同时是负绝对收益。

## 3. 用例与标注

`cases.jsonl` 共 **24 题、137 个要点、20 项计算标注**，四类各 6 题：

| 类别 | ID | 主要目标 |
| --- | --- | --- |
| 查询分解 | QD01～QD06 | 基金×季度×指标矩阵，防止遗漏对象或维度 |
| 多文档对比 | CMP01～CMP06 | 收益排名、行业配置、单股权重、前十持仓集合比较 |
| 引用聚合 | AG01～AG06 | 同结论多文档支持、相同值跨期验证、状态变化 |
| 口径与边界 | BD01～BD06 | 合并调整、金额与份额、分母差异、范围不足、多轮指代 |

每类第 3、6 题为保留测试集，共 8 题；其余 16 题为开发集。
本次仅记录未改产品的固定基线，不用测试集反馈调参。后续开发以 `--split dev` 为主。
两组共享原报告，部分任务共享知识，不能将它们当作独立语料上的泛化评测；后续需增加独立基金或报告期测试集。

每题包括：

- `documents` / `knowledge_bases`：任务对象和可访问范围。
- `turns`：真实用户问法，BD06 含两轮追问。
- `claims`：逐项回答信号和必需证据，不采用“任意一个正确引用就整题通过”。
- `evidence_groups`：外层各组都需要覆盖；内层为同一事实的可替代出处，例如表格与 4.5 节正文。
- `calculations`：输入证据 ID、运算方法、结果、单位与舍入位数，使用 Decimal 复算。
- `reference_answer` / `semantic_rubric`：语义评审参考与检查标准。

`evidence.json` 有 **142 条事实记录**，包含报告、页码、章节、值、单位和原文锚点。
页码采用原始 PDF 的物理页序号，从 1 开始，包含封面，与这四份报告印刷页码一致。
横杠或明确“未持有”在计算中标注为零时，保留原始锚点，不能伪称报告印有数字零。

## 4. 判分口径

自动规则输出的是信号，**不会自动宣布语义正确**：

- `claim_value_signal_rate`：逐要点的关键词、数值信号；数字检查保留符号、数量级和显式单位。
- `claim_evidence_coverage`：每个要点所需来源是否全部存在；同时匹配文件、页码及引用内容中的证据锚点。
- `rule_passed`：数值信号、必需证据、正常结束、SSE 顺序、范围和引用标记唯一性检查均通过。
- `semantic_review=pending`、`final_passed=null`：保留人工语义核查，不把规则通过等同于最终通过。

人工核查必须确认：数值与正确基金/报告期关联、结论由引用支持、计算方向和单位正确、缺失信息处理正确、引用紧邻结论。
规则不能可靠判断否定句、因果推断、引用就近关联、支持/反驳关系或观点是否被原文充分支持。
数值仅在表头统一写单位、合理四舍五入、用不同方向表达差值时，规则可能漏判，需要人工复核。
来源聚合的 UI 合并、相邻片段展示和引用排序也需要未来 P1 的专门测试，不能由当前指标代替。

检索基线直接使用最后一轮原始问题，Top-K 默认为 10，不调用聊天模型、不分解、不补查。
逐题统计去重后的必需证据组覆盖率及全部证据召回情况；这与 Agent 完成率不同。
多轮题使用未消解指代的最后一轮问题作为固定检索基线，不宣称它衡量了会话理解能力。

## 5. 使用

从仓库根目录运行。下载和模型调用都是显式操作；自动化测试不会下载文档或调用真实模型。

```bash
# 仅校验标注结构、范围与计算，不需要网络或原始 PDF
uv run --directory backend python ../eval/finance/run.py

# 首次下载四份固定 PDF，校验哈希、页数、所有证据锚点和事实值
uv run --directory backend python ../eval/finance/run.py --fetch --verify-sources

# 下载后离线复核来源
uv run --directory backend python ../eval/finance/run.py --verify-sources

# 无模型、无 Embedding 密钥的原始问题检索基线
uv run --directory backend python ../eval/finance/run.py --mode retrieval --retriever cosine
uv run --directory backend python ../eval/finance/run.py --mode retrieval --retriever bm25

# 真实模型 + 混合检索；会调用配置中的服务并产生相应成本
uv run --directory backend python ../eval/finance/run.py \
  --mode agent --retriever hybrid --env-file backend/.env --split dev

# 精选题或保留测试集
uv run --directory backend python ../eval/finance/run.py \
  --mode agent --retriever hybrid --env-file backend/.env --only BD01,BD02
uv run --directory backend python ../eval/finance/run.py \
  --mode agent --retriever hybrid --env-file backend/.env --split test

uv run --directory backend pytest tests/e2e/test_finance_eval.py -q
```

结果写入 `eval/results/finance/`，记录数据集指纹、配置、时间、逐题指标。
Agent 结果保存完整回答、引用快照、调用摘要、延迟、Token 和待评审规则。
未缓存原 PDF 的环境仍能运行结构/评分测试；仅原报告核验和真实入库测试跳过。
显式 `--verify-sources` 和实际评测遇到缺文件、哈希变化或锚点不匹配会失败，不跳过、不更换来源。

结构化解析升级后的默认离线门禁通过测试依赖注入使用参考 PDF/DOCX 解析器；
原始 PDF 的金标准核验同样不依赖下载 Docling 模型。
实际 CLI 评测使用产品的 Docling 解析器，不注入参考解析器。证据匹配允许 Docling 表格增加
Markdown 竖线分隔符，但仍要求文件、页码和完整事实行匹配，不更改金标准数值。

多文档对比与引用聚合的两道真实模型冒烟记录见
[P1 交付报告](../../docs/reviews/2026-11-24-multidoc-citations.md)，不等同于全量 24 题评测通过。

本轮结果与限制见 `BASELINE.md`；全部题目及参考要点见 `CASES.md`。
