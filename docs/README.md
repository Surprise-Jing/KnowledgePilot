# KnowledgePilot 功能需求

本文依据[实习任务书](./实习任务书-个人知识管理智能助手.docx)，定义 KnowledgePilot 的功能模块、模块边界与验收要点。除功能需求外，第 4、5、7 节给出工程质量、算法拓展与交付物要求。技术选型与实现见[系统设计文档](./design.md)，接口见[接口契约](./contracts.md)。

系统需要完成以下业务闭环：

**创建知识库 → 上传文档 → 异步解析与建立索引 → 用户提问 → 模型自主调用工具 → 流式回答 → 查看引用与调用轨迹。**

## 1. 范围与优先级

| 优先级 | 完成要求 | 说明 |
| --- | --- | --- |
| P0 | 全部完成 | 知识库、目录与文件、解析入库、检索、工具、Agent 对话、前端 |
| P1 | 至少完成两项 | 查询分解、多文档对比、工具失败降级、引用聚合、MCP＋Skill、20 条评测集 |

评分卡中有 60% 的权重不直接来自功能完成度。各评分维度与本文章节的对应关系如下：

| 评分维度 | 权重 | 本文对应章节 |
| --- | --- | --- |
| 功能完成度 | 30% | 第 2、3 节 |
| 工程质量 | 20% | 第 4 节，以及 2.9 节 |
| 工具与 Agent 设计 | 20% | 2.5～2.7 节、3.3 节 |
| 评测与解释 | 10% | 3.6 节 |
| 答辩与表达 | 10% | 第 7 节（演示录屏与 PPT） |
| 算法拓展 | 10% | 第 5 节 |

以下模块按职责划分，可以在同一个应用中实现，无需分别部署为独立服务。文中“建议”属于实现细化，其余功能要求来自任务书及基础验收标准。

## 2. P0 功能模块

### 2.1 用户隔离与知识库管理

**职责：** 管理知识库及其用户归属，为文件、检索和对话提供数据访问边界。

- 支持多个知识库，允许用户选择一个或多个知识库参与检索。
- 知识库按用户隔离，文件访问、检索和工具调用都必须遵守用户权限。
- 建议提供知识库创建、列表、重命名和删除操作，形成完整管理流程。
- 如支持删除知识库，建议同步处理所属目录、文件及索引，避免残留数据。

**验收要点：** 不同用户不能读取彼此的数据；限定知识库的检索不能返回其他库的内容。

**范围边界：** 需要有可靠的用户身份和归属校验，但任务书没有要求完整的注册、密码找回或角色管理后台。

**身份方式：** 用户以用户名和密码注册登录，身份通过会话 Cookie 传递；不同账号可分别登录以验证隔离效果。

### 2.2 目录与文件管理

**职责：** 组织知识库中的文档，维护文件位置与元信息。

- 支持任意层级目录，不将目录深度固定为一层或两层。
- 支持文件上传、删除、重命名和移动。
- 建议提供目录创建、列表、重命名、移动和删除，并明确非空目录的删除规则。
- 建议文件列表展示文件名、类型、所属目录和解析状态。
- 文件删除后同步清理对应索引；重命名或移动后，引用来源仍应能够正确定位。

**验收要点：** 前端能完成文件管理操作；删除文档后检索不到其内容；目录移动不能形成循环父子关系。

**移动范围：** 文件与目录只在同一知识库内移动，不支持跨知识库移动，以免索引归属与访问权限需要重建。

### 2.3 文档解析与入库

**职责：** 将原始文件转换为带来源位置、可检索的知识片段。

- 支持 PDF、Word、TXT 文档解析。
- 异步执行解析与入库，提供排队、解析中、成功、失败四类可见状态。
- 失败时提供明确原因，允许用户重试。
- 按内容去重，避免相同内容重复入库；去重不能破坏用户隔离或多库归属。
- 对解析内容切分片段并建立索引；片段必须保留来源文档和位置。
- 建议 PDF 使用页码定位，Word 使用标题路径或段落定位，TXT 使用行号或字符范围定位。
- 删除文档时同步清理片段和索引；建议防止正在执行的入库任务在删除后重新写入数据。
- 同一文档同一时间只能有一个解析任务；重复点击重试不能产生并发任务或重复片段。
- 服务重启后，处于排队或解析中的任务应恢复执行，或被标记为失败并允许重试，不能长期停留在中间状态。
- TXT 需要处理常见中文编码，至少支持 UTF-8，建议兼容 GBK；无法识别编码时应失败并说明原因，不能入库乱码。

**验收要点：** 三种格式均能成功入库；失败原因可见且能重试；重复上传不会产生重复检索内容；片段可定位回原文；解析过程中重启服务后，任务状态最终变为成功或失败。

**范围边界：** 任务书未明确要求扫描 PDF 的 OCR，也未限定 Word 扩展名（`.doc` 或 `.docx`）。实际支持的格式、大小限制和不支持的情况应在实现后写明，不能将不支持的文件显示为解析成功。

### 2.4 知识检索

**职责：** 根据查询和知识库范围返回可用于回答的文档片段。

- 接收查询内容和一个或多个知识库的过滤条件。
- 严格限制检索范围，并校验用户权限。
- 返回片段内容、来源文档、来源位置和相关度。
- 对结果去重，并按相关度排序。
- 建议支持结果数量限制；没有结果时返回明确的空结果。

**验收要点：** 单库和多库过滤均有效；结果字段完整；重复结果受到控制；删除的文档不再出现。

**范围边界：** 任务书未强制指定向量检索、关键词检索或混合检索方案，技术方案可自行选择。

### 2.5 工具接口

**职责：** 将知识库能力封装为模型可以自主选择和调用的工具。

至少实现以下三个工具。名称及字段是建议，实际实现可调整，但能力必须覆盖。

| 工具 | 主要输入 | 主要输出 |
| --- | --- | --- |
| `search_chunks` 检索片段 | 查询、知识库范围、结果数量 | 内容、来源、位置、相关度 |
| `list_files` 列出文件 | 知识库、目录；可选分页条件 | 文件标识、名称、目录、解析状态 |
| `read_document` 读取原文 | 文档标识；可选位置或范围 | 对应原文及来源位置 |

- 每个工具需要清晰说明用途、参数类型、必填项和取值约束。
- 返回机器可处理的结果和结构化错误。
- 建议错误包含错误码、说明和是否可重试，覆盖参数错误、权限不足、文档不存在、未解析和内部异常等情况。
- 工具自身执行权限校验，不依赖模型判断权限。
- 建议限制单次原文读取长度，避免工具输出超过上下文容量；内容被截断时，在结果中标明并给出继续读取的位置。

以下工具不是任务书的最低要求，可按需增加，用于支持指代消解、多文档对比和工具抽象设计：

| 工具 | 用途 |
| --- | --- |
| `list_knowledge_bases` 列出知识库 | 让模型确认可用的检索范围 |
| `get_document_outline` 读取文档大纲 | 返回标题结构、页数和元信息，帮助模型定位后再读取原文 |

**验收要点：** 模型能根据工具说明正确调用；非法参数和越权访问返回结构化错误；读取原文能定位到对应文档内容。

### 2.6 Agent 与多轮对话

**职责：** 管理模型、工具执行和会话上下文，生成基于知识库的回答。

- 模型根据问题自主选择工具，而不是为所有问题固定执行同一组工具。
- 支持“模型决策 → 工具执行 → 结果回传 → 继续决策或回答”的循环。
- 设置最大执行步数，达到上限时明确结束或提示。
- 支持多轮对话和指代消解，例如正确理解“这份文档”“刚才提到的方法”。
- 支持回答流式输出。
- 回答中的引用可追溯到来源片段或原文位置。
- 模型异常时给出明确提示，不能让界面一直等待。建议为模型调用和工具调用分别设置超时。

**上下文管理：**

- 为历史消息、工具结果和系统提示分配上下文预算，超出时按明确规则截断或摘要早期消息。
- 会话内记录近期涉及的文档和引用，供“这份文档”“刚才提到的方法”等指代解析使用。
- 多轮追问时可以复用上一轮的检索结果，但回答引用仍需指向真实片段。

**流式事件：** 建议前后端约定统一的流式事件格式，例如基于 SSE，并至少区分以下事件：

| 事件 | 内容 |
| --- | --- |
| `token` | 回答文本增量 |
| `tool_call` | 工具名称和参数摘要，工具开始执行时推送 |
| `tool_result` | 执行状态、结果摘要或结构化错误 |
| `citation` | 引用标识与来源片段的对应关系 |
| `error` | 模型或系统异常的提示信息 |
| `done` | 本次回答结束，包含结束原因，例如正常完成或达到最大步数 |

工具轨迹应随执行过程实时推送，而不是等回答结束后再统一返回。

**验收要点：** 模型可以连续自主调用工具；追问能使用前文信息；回答逐步显示；工具轨迹在回答过程中实时出现；超步数、超时或模型异常时能正常结束流程。

**范围边界：** 当前会话的上下文管理属于 P0；跨会话长期记忆不在范围内。

**模型模式：** 未配置模型时，系统可以退化为基于检索结果的原文摘录回答，便于开发调试。但这种模式无法体现“模型自主选择工具”，不能用于 P0 验收。演示时必须使用公开 API 或本地部署的模型（如 Ollama），并选择支持工具调用的模型。

### 2.7 引用与工具调用轨迹

**职责：** 让用户知道回答依据什么资料，以及系统执行了哪些工具操作。

- 回答引用关联到真实文档和具体来源位置。
- 建议由模型在回答中输出引用标记（如 `[c12]`），后端将标记映射到片段标识和来源位置，再交给前端展示。
- 后端只接受本次提问中工具实际返回过的片段作为引用；模型给出不存在或未返回的引用标识时应丢弃，并记录到调用记录中，防止编造引用。
- 前端可查看引用对应的内容与位置。
- 工具调用轨迹可见；建议展示工具名称、参数摘要、执行状态、结果摘要和错误信息。
- 建议为一次提问关联完整调用记录，方便定位问题。
- 轨迹展示可观测的工具行为，不要求展示模型内部思考过程。

**验收要点：** 用户能从回答找到对应原文；回答中不出现指向未检索内容的引用；能查看本次回答调用了哪些工具及执行结果。

**范围边界：** 基础调用轨迹展示是 P0；复杂 Trace 图形化分析属于后续扩展。

### 2.8 前端交互

**职责：** 提供可操作的完整演示入口，可以使用现成 UI 库，但不能只通过 CLI 或 Postman 演示。

| 页面或区域 | 需要覆盖的操作 |
| --- | --- |
| 知识库与目录区域 | 查看和选择知识库、浏览目录、执行管理操作 |
| 文件区域 | 上传、删除、重命名、移动；查看解析状态及失败原因；触发重试 |
| 对话区域 | 选择知识库范围、提问、多轮追问、查看流式回答及异常提示 |
| 引用区域 | 查看来源文档、位置和对应内容 |
| 工具轨迹区域 | 查看当前提问的工具调用过程与结果 |

**验收要点：** 用户不需要手工调用后端接口，即可完成上传、提问、查看引用和工具轨迹的全流程。

### 2.9 持久化与运行支撑

本模块承接任务书的环境约束和基础验收要求，为上述功能提供支撑。

- 一条命令本地启动，不依赖公司基础设施。
- 模型可使用公开 API 或本地部署方案；密钥通过环境变量提供。
- 只使用公开或脱敏数据。
- 文档、归属关系和检索数据应持久保存，重启后不丢失。
- 建议会话与调用记录也持久保存，便于多轮使用和排查问题。
- README 应提供真实可执行的启动步骤，并说明技术选型理由与替代方案；具体命令在实现后补充。

**验收要点：** 在说明的环境下可按 README 启动；重启后仍可访问已有知识库并检索文档；密钥不写入代码。

## 3. P1 功能模块

以下六项中至少完成两项。

### 3.1 查询分解

- 将复杂问题拆分为多个可检索的子问题。
- 分别检索，再综合结果生成回答。
- 建议限制子问题数量，并将分解与执行情况关联到调用记录。

**验收示例：** “这两份方案分别如何处理检索和错误恢复？”能拆分检索维度，并在最终回答中覆盖所有子问题。

### 3.2 多文档对比

- 识别或选定需要对比的文档。
- 按问题要求提取相同维度的信息，输出共同点和差异。
- 对各文档的结论分别给出引用，资料缺失时明确说明。

**验收示例：** 对比两份方案的检索方式、存储方式和限制，结果有对应来源，不把不同文档的信息混用。

### 3.3 工具失败降级

- 识别工具超时、执行失败和暂不可用等情况。
- 根据失败原因采取有限重试、替代工具或部分结果回答等策略。
- 向用户说明未完成的部分；重试必须受次数或总步数限制。

**验收示例：** 原文读取失败时，可依据已检索片段回答并说明限制；没有足够依据时明确告知无法完成。

**与 P0 的区别：** P0 要求结构化工具错误和明确异常提示；P1 进一步要求系统具备恢复或替代执行策略。

### 3.4 引用聚合

- 合并重复引用，统一来源标识。
- 支持一个结论关联多个来源，并保留各自定位信息。
- 建议对同文档相邻片段进行适当聚合，减少重复展示。

**验收示例：** 多次检索到同一片段时，不重复堆叠引用；同一结论由多份文档支持时，可查看所有来源。

### 3.5 MCP 与 Skill 暴露

- 至少将一个工具封装为本地 stdio MCP Server。
- 提供 `SKILL.md`，说明适用场景、工具使用方式及调用示例。
- 确保外部调用与应用内部使用一致的权限、参数和错误规则。
- 环境不允许 MCP 时，实现等价的“工具契约＋分发接口”，并说明与 MCP 的映射关系。

**验收要点：** 可以按说明从外部调用至少一个知识库工具；Skill 包和调用示例可演示、可复现。

### 3.6 评测集与评测报告

- 建立 20 条评测用例。
- 建议覆盖单库、多库、多轮指代、工具选择、引用定位、无结果和异常场景。
- 每条用例建议包含测试数据、问题或操作、预期行为和判定标准。
- 记录实际结果并分析失败原因，形成评测报告。
- 建议统计检索命中、回答正确性、引用正确性、工具调用成功情况及耗时。

**验收要点：** 20 条用例可重复执行，结果可核对；报告能说明主要失败类型及改进方向。

**与算法拓展的关系：** 评测集同时作为第 5 节算法优化的对照基准，建议评测脚本能够切换检索或回答策略，并输出可比较的指标。

## 4. 工程质量要求

本节对应评分卡中“工程质量”（20%）的观察点：分层、异常、幂等、日志、可复现。

### 4.1 分层

- 至少区分接口层、业务服务层、数据访问层、工具层和 Agent 层。
- 工具层只依赖业务服务，不直接拼接数据库查询；应用内 Agent、MCP Server 和 HTTP 接口复用同一套工具实现。
- 解析器、检索器和模型客户端通过接口抽象，便于替换实现和在评测中做对照实验。

### 4.2 异常处理

- 定义统一的错误结构，接口错误和工具错误使用一致的错误码体系。
- 区分用户可修正的错误（参数错误、权限不足、文件不支持）和系统错误（模型超时、内部异常），前端分别给出提示。
- 后台任务的异常不能导致服务退出，失败原因写入任务记录。

### 4.3 幂等

| 操作 | 幂等要求 |
| --- | --- |
| 上传相同内容的文件 | 不重复解析和入库，返回已有文档或明确的重复提示 |
| 重试解析 | 同一文档不并发执行多个任务，重试成功后不产生重复片段 |
| 删除文档或目录 | 重复删除返回一致结果，不报内部错误 |
| 重启服务 | 未完成的任务能恢复或标记为失败，不产生半写入数据 |

### 4.4 日志与可观测性

- 使用结构化日志，记录请求、解析任务、工具调用和模型调用的关键事件。
- 每次请求和每次提问生成唯一标识，日志、工具调用记录和前端轨迹通过该标识关联。
- 记录模型调用耗时和 token 用量，供评测报告统计。
- 日志中不输出密钥和完整的文档原文。

### 4.5 测试与可复现

- 核心流程具备自动化测试：入库、检索隔离、删除后不可检索、工具参数校验和结构化错误。
- 模型调用可替换为固定输出的测试实现，使测试不依赖网络和密钥。
- 提供示例数据和 `.env.example`，新环境按 README 操作即可复现演示。

## 5. 算法拓展

在完成工程功能的基础上设计优化算法，并用评测数据说明效果。算法拓展必须带有对照实验，不能只描述做法。

### 5.1 方向

可选择以下一到两个方向深入完成。

| 方向 | 做法示例 | 评测指标 |
| --- | --- | --- |
| 混合检索 | 关键词检索与向量检索并行，使用 RRF 等方法融合排序 | 检索命中率、MRR |
| 重排 | 对召回结果使用交叉编码器或模型打分重排 | Top-K 命中率、引用正确率 |
| 切块策略 | 对比固定长度切块、按标题或段落结构切块、带重叠切块 | 检索命中率、回答正确率 |
| 查询改写 | 结合会话历史改写追问，补全指代对象后再检索 | 多轮用例的检索命中率 |
| 工具调用策略 | 优化工具说明或增加规划步骤，减少无效调用 | 平均工具调用次数、耗时、成功率 |

P2 中的多 Agent 分工、长期记忆和 Trace 可视化也可作为拓展方向，但优先级低于上表中直接影响回答质量的方向。

### 5.2 实验要求

- 使用 3.6 节的评测集作为基准，必要时补充针对该方向的用例。
- 记录基线方案与优化方案在同一数据集上的指标对比。
- 说明优化带来的收益、代价（耗时、成本、复杂度）以及没有改善的场景。
- 实验结论写入评测报告，并在答辩中说明取舍。

## 6. 模块协作与数据关系

数据按以下关系组织，表结构见[数据模型设计](./data-model.md)：

- 用户拥有知识库；知识库包含目录和文档；目录通过父目录关系形成树。
- 文档关联解析任务、原文内容、知识片段和检索索引。
- 知识片段记录文档标识、内容和来源位置；索引关联片段及知识库范围。
- 会话包含消息；一次提问关联工具调用记录和回答引用。
- 引用关联来源文档及片段或位置，不能只保存无法回查的展示文本。

各模块的主要协作流程：

1. **入库：** 前端上传文件，文件模块保存记录，解析任务异步处理，生成片段和索引，前端展示状态。
2. **问答：** 前端提交问题和知识库范围，Agent 自主调用工具，检索或读取资料，再流式返回回答及引用。
3. **删除：** 文件模块删除文档，同步清理片段和索引，并防止未结束的入库任务写回已删除内容。
4. **追溯：** 前端根据引用读取对应来源，根据提问标识查看工具调用记录。

## 8. 功能验收清单

### P0

- 支持多个知识库，按用户隔离。
- 支持任意层级目录和文件上传、删除、重命名、移动。
- PDF、Word、TXT 均可解析入库。
- 异步状态可见，失败有原因且可重试；重启后任务不会卡在中间状态。
- 按内容去重，片段保留来源位置。
- 单库和多库检索不串库，结果包含内容、来源、位置和相关度，并去重排序。
- 至少提供检索片段、列出文件、读取原文三个工具。
- 工具有清晰说明、参数约束和结构化错误。
- 使用真实模型演示，模型自主调用工具，并限制最大执行步数。
- 支持多轮对话、指代消解、流式回答和可追溯引用；引用只指向工具实际返回的片段。
- 工具调用轨迹实时可查看，模型异常和超时有明确提示。
- 前端可完成文件管理、提问、查看引用和工具轨迹。
- 删除文档后检索不到其内容，重启后数据不丢失。
- 一条命令本地启动，配置和 README 可复现。
