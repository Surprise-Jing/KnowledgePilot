# P0 验收与删除焦点收口设计

## Intent

在不重复开发已完成的 P0、MCP + Skill、工具降级和 20 条评测的前提下，对当前 `dev` 基线做最终验收，并修复评测 E1 暴露的上下文误导问题。目标是让验收结果真实可复现：真实模型运行失败、环境问题和未覆盖项都必须记录，不能用 Mock 成功替代真实运行。

本轮暂不验收或修改正在调整中的 PDF 文档处理流程。PDF 相关验收作为延期项，待该流程稳定后单独执行。

## Goals

- 执行后端测试、Ruff、格式检查、前端测试和构建。
- 在尽可能干净的环境检查 `./start.sh`，记录依赖、端口、配置和联网条件造成的阻塞。
- 使用真实模型完成不依赖 PDF 处理路径的端到端冒烟；若现有冒烟脚本强制经过 PDF，则拆出 TXT/DOCX 子集或明确记录延期。
- 补充真实中文 DOCX/TXT 的解析、检索和引用定位验收。
- 验证多知识库隔离、多轮追问、引用定位、删除后检索和删除后追问行为。
- 修复删除文档后模型将“当前无法访问”误说成“上一轮没有依据”的问题。
- 评估 TXT 分块粒度；只有在测试证明确有收益且不影响现有契约时才做局部调整。
- 输出完整的未通过项、已知限制和 PDF 延期项。

## Non-goals

- 不重做已实现的 MCP、Skill、工具降级、20 条评测和一键启动。
- 不在本轮修改 PDF 解析、PDF 分页、PDF 分块或 PDF 引用定位流程。
- 不为了让测试通过而引入假模型、假检索结果或硬编码演示数据。
- 不改变现有 HTTP/SSE/工具公共契约和数据库结构，除非验收发现明确的契约级 P0 阻塞；若需要，先停下报告差异。
- 不把 PDF 相关失败隐藏为“通过”；统一标记为延期或未验证。

## Constraints

- 遵守 `AGENTS.md` 的文件所有权和分层规则。
- 保持现有 API 与数据库结构稳定。
- 测试不得依赖网络或模型密钥；真实模型冒烟和评测作为独立的验收命令，失败必须如实记录。
- 不把密钥、文档全文或个人信息写入日志、测试或提交。
- SQLite 连接保持短事务，不跨异步等待持有连接。
- 当前用户正在修改 PDF 处理流程，验收和修改不得干扰其工作。

## Approaches

### 1. 推荐：验收优先 + 删除焦点最小修复

先跑门禁和非 PDF 验收，再用现有引用快照增强会话焦点：删除后保留历史引用的文档身份和文件名，并明确告诉模型该文档已经删除、历史回答仍基于当时返回的片段、当前不能重新读取。必要时增加删除文档后的回归测试。TXT 分块只在验收测量表明引用范围明显过粗且局部调整安全时修改。

优点：改动小、审计语义正确、不会改写历史回答，也不会影响正在调整的 PDF 流程。

### 2. 历史回答重写

删除文档后修改历史 assistant 消息，在回答末尾追加删除说明。

不采用：会改变已经持久化的回答和审计记录，可能破坏引用展示，且不能解决模型当前工具上下文不知道删除事实的问题。

### 3. 全面重做上下文与检索

同时重设计会话焦点、TXT 分块和混合检索，并以扩展评测作为验收依据。

不采用：超出 P0 收尾范围，变更面大；当前 20 条真实 Agent 评测已经通过，不能证明全面重做是必要的；也会与 PDF 流程调整相互干扰。

## Proposed design

### 验收顺序

1. 记录工作区状态和当前配置，不读取或输出任何密钥。
2. 执行后端全量测试、Ruff 检查、格式检查、前端测试和构建。
3. 用隔离数据目录检查 `start.sh` 的构建、服务启动、健康检查和退出清理；模型配置缺失只能验证启动行为，不得声称 Agent 成功。
4. 运行不经过 PDF 处理路径的真实模型冒烟；验证上传中文 TXT/DOCX、解析成功、检索、流式回答、引用、轨迹、多轮和删除后行为。
5. 运行中文 DOCX/TXT 专项验收，检查段落/表格或行号位置与引用内容一致。
6. 验证多库范围不会串库，删除后新检索不返回内容，历史追问能区分“当时有依据”和“现在已删除”。
7. 记录 PDF 相关验收为延期，不修改 PDF 代码。

### 删除后的会话焦点

当前引用快照在删除文档时可能通过外键 `ON DELETE SET NULL` 清空 `citations.document_id`，但保留文件名、位置和内容快照。会话焦点构建逻辑应同时识别：

- 仍存在的文档：提供可继续使用 `read_document` 的文档身份。
- 已删除的历史引用：提供文件名和明确状态“文档已删除；历史引用来自删除前工具结果；当前不能调用工具重新读取”。

删除状态只用于解释历史依据，不得让工具重新访问已删除文档，也不得把历史快照伪装成当前检索结果。若现有焦点数据不足以稳定识别已删除文档，优先通过引用快照中的 `filename`、`location` 和 `content` 设计只读的历史删除提示；任何需要新增持久化字段的方案先报告契约/数据库变更，不直接实现。

### TXT 分块评估

先以当前实现测量：每个片段的行范围、引用覆盖行数、目标行命中率和现有评测结果。若要调整，只考虑按空行/小节或更小行窗口切分，并保持 `txt_lines` 位置结构和检索 API 不变。调整前后用同一批中文 TXT 用例比较片段数量、引用范围、命中率、工具调用和延迟；没有明确收益时保持现状。

## Acceptance evidence

交付报告必须分开列出：

- 通过的本地门禁命令及关键输出。
- 真实模型冒烟命令、配置条件、覆盖范围和关键结果。
- 未通过、未运行、环境阻塞和真实服务波动。
- PDF 相关延期项及重新验收前置条件。
- 删除焦点修复前后的回归行为。
- 是否修改公共接口、数据库结构或新增依赖。

只有所有已纳入本轮的实现和验证完成后，才可以声称本轮收口完成；PDF 相关验收不得计入本轮“全部通过”。
