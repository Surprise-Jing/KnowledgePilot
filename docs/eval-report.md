## 2. 指标定义

**位置匹配**：引用或检索命中的 `filename` 等于 `relevant.file`，且（若给出）`kind`、`table` 相同、`[start, end]` 与片段位置区间有重叠、`heading` 在 `heading_path` 中。

检索模式（不调用聊天模型；13 条有检索目标的用例，排除无答案、异常、`list_files` 类和 T2 全文阅读）：

- **Hit@k**：top k 中至少有一个相关片段的查询占比。**MRR**：首个相关片段排名倒数的均值（top_k=10 内没有记 0）。
- 语料一次性以 `hybrid` 入库（写入向量），每种策略各建一个同数据目录的应用实例，通过 `POST /api/search` 查询所选知识库。

Agent 模式（真实模型、完整 SSE 对话）：

- **通过**：最后一轮满足所有检查——`stop_reason`（默认 `answered`）、期望错误码、`expect_tools` 都被调用且没有 `forbidden_tools`、`answer_keywords` 每组至少命中一个同义写法（忽略大小写、空格和千分位）、不含 `forbidden_keywords`、无答案用例包含“没有找到/未提及/无法确定…”等表述、有 `relevant` 的用例至少一个引用位置匹配、不引用 `forbidden_files`。
- **回答要点命中率**：每个用例命中的要点组数 / 要点组数，再对用例取平均。
- **引用正确率**：有 `relevant` 的用例中，位置匹配的引用数 / 全部引用数（只统计最后一轮的有效 `citation` 事件）。**引用命中用例率**：至少有一个正确引用的用例占比。
- **工具选择正确率**：有 `expect_tools` 的用例中工具检查全部通过的占比。**无答案识别率**：`expect_no_answer` 用例中明确说明没有答案的占比。
- **工具调用成功率**：`tool_result.status == success` / 全部工具调用（含重试）。**平均工具调用次数**：所有轮次的工具调用数 / 用例数。
- **降级运行**：`done.degraded == true` 的轮次数。
- **首字延迟（TTFT）**：发送请求到第一个 `token` 事件；**总耗时**：到流结束。均按轮次统计 P50 / P95（线性插值）。
- **Token**：`done.usage` 中输入 / 输出 token 之和。
- **失败类型**（按顺序取第一个成立的）：异常处理（异常类用例或 stop_reason/错误码不符）→ 工具选择错误 → 检索未命中（把模型本轮的每次 `search_chunks` 参数在同一数据上重放 `/api/search`，都没有相关片段，且没有成功 `read_document` 相关文件）→ 引用错误 → 回答错误。

运行方式：应用在进程内用 `create_app(Settings(_env_file=<env>, data_dir=<临时目录>, …))` 构建。检索模式用 TestClient；Agent 模式用 uvicorn 在后台线程监听 `127.0.0.1` 随机端口，因为 TestClient 会把流式响应缓冲到结束，无法测首字延迟。带 `overrides` 的用例（E2）用同一数据目录上的第二个应用实例，不修改运行中实例的状态。

## 5. 失败与问题分析

两次 Agent 运行均没有失败用例，以下按失败类型列出检索评测中的失败和 Agent 运行中“通过但不理想”的情况。

### 5.1 检索未命中

- cosine / bm25 在 F3、M2、T3 全部未命中（见第 3 节），根因是词法检索不能跨语言。bm25 与 cosine 在 13 条查询上排名完全相同：语料只有 21 个片段且同库片段的主题差异大，BM25 的长度归一化和 IDF 没有拉开差距。
- hybrid 的 Hit@1 低于纯 vector（0.769 vs 0.923）：当只有一路召回相关片段时，RRF 会系统性地压低它。

### 5.2 引用错误（未导致失败，但拉低引用正确率）

- **T3（1/6）**：问题要求“读取全文、列出所有美元金额”，模型先逐页概括全文并逐页引用，金额只在第 4 页。其他 5 个引用支撑的是概括内容，本身不是错误引用；指标把非 `relevant` 位置都记为不正确，低估了实际质量。
- **C1（1/2）**：除表 1 第 2 行外还引用了“第三章 差旅与报销”段落（支撑“超出标准由个人承担”），内容正确但不在期望位置。
- **TXT 定位粒度粗**：TXT 按行合并到约 800 字一个片段，用户指南 89 行只有 3 个片段（第 1–33、34–67、68–89 行），F1、C3、M1 的“正确引用”实际只定位到 30 行左右的范围。M1 第一轮同时引用了 3 个片段。引用的行级精确度受解析分块限制，不是模型问题。

### 5.3 异常处理

- **E2**：`PK_LLM_TIMEOUT=0.001` 时稳定得到 `error(model_timeout)` 与 `done(stop_reason=timeout)`，消息状态为失败，符合契约 §5.4。
- **E1**：删除文档后第二轮检索为空、`list_files` 返回 0 个文件，模型明确说明没有找到，未引用已删除文档，判为通过。但有两点值得注意：
  1. 删除文档时 `citations.document_id` 被置空（`ON DELETE SET NULL`），会话焦点因此不再包含这份文档，模型无从调用 `read_document`，用例设计中预期的 `document_not_found` 工具错误路径没有被触发。
  2. 模型在回答中说“上一轮回答中提到的‘预计停机 6 小时’并没有资料依据”。这一句是错的：上一轮有依据，只是文档后来被删除了。原因是焦点和工具结果都没有告诉模型“文档已被删除”。
- 降级（§10）：基线 `e3d53f1` 尚未合入 B2，两次运行都没有降级（0/24），工具调用全部成功。

### 5.4 工具选择错误、回答错误

无。T1–T3 均按预期调用 `list_files` / `read_document`；无答案用例均没有编造。

## 6. 成本与延迟

- hybrid 下 20 个用例（24 轮）共 154k 输入 / 7.4k 输出 token，平均每轮约 6.7k token，主要是系统提示、工具定义和工具结果（单次工具结果最多 8000 字符）。最贵的几轮是多次检索的无答案用例：N1 19,170 输入 token（3 次检索）、S3 15,979（3 次检索 + list_files），因为模型会换说法反复确认“确实没有”。
- 首字延迟 P50 约 6 s，包括一到两次模型调用和工具执行；向量检索每次增加约 0.46 s 的 Embedding 请求（检索模式实测）。P95 首字 12–14 s，来自多步工具调用的轮次（S3 12.4 s、N1 15.1 s）。
- 单次运行的波动：两次运行的 P50 相差约 0.3 s，P95 相差约 2 s；每条用例只跑了一次，模型非确定性带来的波动没有用重复运行量化。

## 7. 结论与改进方向

结论：

1. 在这 20 条用例上，真实模型 + hybrid 检索的 Agent 全部通过：回答要点、无答案拒答、工具选择、范围隔离、多轮指代和超时处理都符合预期。评测集偏小、通过率已到上限，下一轮需要更难、更多的用例才能区分改进（见下）。
2. 检索层面，**vector 在本语料上优于 hybrid**（MRR 0.962 vs 0.840），差距全部来自跨语言查询；同语言查询四种策略在 Hit@1 上基本相同。保持 `.env.example` 推荐的 hybrid 是合理的（中文同语言资料仍需要关键词精确匹配，例如型号、编号），但需要处理 RRF 对单路召回的压制。
3. 检索弱时 Agent 能用 `list_files` + `read_document` 补救，代价是约 1.2 倍工具调用、1.17 倍输入 token 和更长的尾延迟。

改进方向（按优先级）：

| 方向 | 负责 | 依据 |
| --- | --- | --- |
| hybrid 融合加权或按查询语言调整：一路无正分候选时（如中文查询 vs 英文片段，BM25 全 0）只用向量排名，或给向量一路更高权重 | A2 | F3/M2/T3 在 hybrid 下排第 3–4，vector 下第 1–2 |
| TXT 分块按空行 / 小节切分并降低单块上限，提高行级引用精度 | A | 用户指南 89 行只分成 3 块，引用定位到约 30 行 |
| 删除文档后在会话焦点中保留“已删除的文档”提示，让模型说明“文档已被删除”而不是否认上一轮的依据 | B | E1 第二轮的错误表述 |
| 无答案场景限制重复检索（如同一意图最多 2 次换说法） | B | N1、S3 单轮 16–19k token |
| 评测集扩展：更多跨语言、近义干扰、同库多文档对比、需要多次 `read_document` 翻页（`next_ordinal`）的长文档、降级场景（B2 合入后注入 Embedding 故障验证 `done.degraded`），每个配置重复 3 次报告均值和方差 | D | 当前通过率已到上限；单次运行 |
| 引用正确率改为“引用是否支撑所写内容”的判定（为全文概括类问题标注多处 `relevant`，或引入人工/模型评审） | D | T3、C1 的引用正确率被低估 |
