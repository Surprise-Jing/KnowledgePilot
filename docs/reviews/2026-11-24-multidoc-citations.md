# 多文档对比与引用聚合交付记录

日期：2026-11-24。范围由主 Agent 串行实现，保留工作区同时进行的结构化解析改动。
本轮不增加独立查询规划器、数据库迁移或依赖。

## 1. 已实现行为

### 多文档对比

- HTTP 搜索和 `search_chunks` 工具支持可选 `document_ids`，先验证权限、范围，再限定文档召回；在 Embedding 请求返回后重新验证，避免期间删除导致范围失效。
- 指定多份文档时按每份相关度轮流取结果，`top_k` 仍是总上限。hybrid 两路召回先按文档保留候选，再逐文档 RRF 融合，避免另一份文档在全局候选截断时被排除。
- 检索只在同文档内按内容去重；不同报告的相同文本保留各自来源、位置和引用标记。
- 工具返回 `document_coverage`，逐文档报告本次返回条数。0 表示本次未覆盖，不表示原文未提及；轨迹摘要提示未覆盖文档数。
- 系统提示约定确认对象/版本、按“文档×维度”比较、各单元就近引用、保留冲突、说明缺失及计算口径。模型自主决定是否补查、读取原文或回答。

这些回答规范由模型执行；程序没有自动证明每个结论的语义正确性，也不会强制每个问题都走固定工具流程。

### 引用聚合

- 回答正文中连续有效引用聚合为来源徽标，展开后列出各条文件名、位置和标记，点击仍定位到对应原文。
- 同一连续引用组内重复标记去重；不同结论、未知标记、代码、链接和表格单元格边界保持隔离。
- 引用面板按同文档结构相同的相邻位置或重叠字符窗口分组，保留每条快照与独立跳转，不将原文拼接为一段。
- 来源组从已保存的正文和引用派生，刷新/历史会话不需要新增存储字段。已删除来源保留快照，组内不凭同名文件推断已删除文档的数量。

### 证据复用

真实模型首轮在四报告聚合题上反复列文件、重复检索，达到原有 6 步上限且未输出答案。
针对已观察到的问题，补充：

- 本 run 的来源索引：复用实际工具返回过的文档 ID、文件名和标记，有固定字符及内存上限；不存放正文、不表示任务已经完成。
- 旧工具消息压缩时，除摘要外保留少量分文档原文摘录；最新结果仍完整保留。
- 证据齐备时直接综合回答，不为了引用相同章节反复检索。需要完整依据时继续使用现有工具。

该机制没有新模型调用，也不替代模型的任务规划。详见 `docs/contracts.md` v1.8 §12。

## 2. 修改范围

- 后端：`SearchRequest`、检索服务、搜索工具与说明、Agent 提示和上下文来源记忆。
- 前端：搜索请求类型、引用 Markdown 插件、回答来源弹层、引用面板分组；测试 fixture 补齐当前解析契约字段。
- 评测兼容：旧分块函数导入改为显式测试用参考解析器；评测配置路径兼容 `uv --directory`；证据匹配忽略 Markdown 表格分隔符，仍要求原文件、页码和完整事实行匹配。
- 测试：新增文档对比/权限/候选覆盖/降级/历史引用、证据记忆、来源聚合交互及相邻位置测试。
- 文档：共享契约、任务增量和本报告。未提交其他任务的解析实现，也未修改评测问题、标准数值或证据锚点来提高分数。

## 4. 查询分解的取舍

当前保留模型自主拆解和调度。优先补齐工具可用性、来源覆盖与证据复用，避免额外固定 Planner 增加一次模型请求却没有可证明的收益。

如果后续评测暴露问题，可分别实验：

1. **依赖任务**：先求两份持仓的交集，再查这些对象的其他指标；前置结果决定下一步查询对象。
2. **覆盖检查与补查**：检查用户要求的文档/维度是否缺证据，在预算内只补缺口。
3. **追问改写与复用**：消解“这份报告”等指代，复用已确认的文档 ID 和已有结果，减少重复调用。

这些能力可直接融入现有 Agent；只有同预算的真实模型对照证明有效，才考虑独立规划阶段。
